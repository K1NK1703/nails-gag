# Что сделать до запуска

Памятка для оператора сайта nails.gag по персональным данным (152-ФЗ). Документы сайта:

- политика обработки персональных данных — `nails-gag-web/src/content/privacy.ts` (страница `/privacy`);
- пользовательское соглашение (оферта: правила записи, отмены, оплаты и гарантии) — `nails-gag-web/src/content/terms.ts` (страница `/terms`);
- тексты согласий — `nails-gag-web/src/content/consents.ts`;
- договор поручения обработки с разработчиком — шаблон в этой папке.

> Это не юридическая консультация. Перед публикацией сайта и подачей уведомлений покажите политику, соглашение, согласия и шаблоны юристу.

## Почему это важно

С 30 мая 2025 года штрафы по ст. 13.11 КоАП РФ заметно выросли: отдельно наказываются неподача уведомления в Роскомнадзор, обработка без согласия или без его надлежащей формы, а особенно утечки (для утечек — оборотные и многомиллионные штрафы для организаций, для граждан и ИП суммы ниже, но тоже ощутимые). Точные суммы для самозанятой уточните у юриста. Самый дешёвый способ их избежать — пройти список ниже до первого клиента.

## Чек-лист

1. **Заполнить плейсхолдеры.** Все они объявлены в `nails-gag-web/src/content/placeholders.ts` и подставляются в политику, пользовательское соглашение, `consents.ts` и строку об исполнителе в подвале сайта:
   - `OPERATOR_FIO` — фамилия, имя, отчество оператора (Алина);
   - `OPERATOR_INN` — ИНН самозанятой;
   - `OPERATOR_EMAIL` — личная почта для обращений по персональным данным;
   - `OPERATOR_CITY` — город (по умолчанию «Санкт-Петербург»); домашний адрес на сайте не публикуется;
   - `HOSTING_PROVIDER` — наименование российского хостинг-провайдера, например «ООО „…“»;
   - `DEVELOPER_FIO` — ФИО разработчика сайта (обработчик по поручению);
   - `SMS_PROVIDER` — российский СМС-провайдер; пока он не подключён, можно оставить формулировку «при подключении», но плейсхолдер заменить на название или убрать пункт;
   - домен сайта берётся из переменной `VITE_SITE_URL` (`.env`); без неё в тексте останется `{{SITE_URL}}`.

   После сборки `npm run build && npm run check-dist` выведет предупреждение со списком незаполненных `{{…}}`. Перед публикацией предупреждения быть не должно.

2. **Подать уведомление об обработке персональных данных** (ст. 22 152-ФЗ) — до начала обработки, то есть до открытия регистрации и онлайн-записи. Подаётся через Госуслуги («Уведомление об обработке персональных данных») или на портале pd.rkn.gov.ru с подписью через Госуслуги. Что указать:

   | Поле | Что писать |
   |---|---|
   | Наименование (ФИО) оператора | ФИО полностью, статус — физическое лицо, плательщик НПД |
   | ИНН | ИНН самозанятой |
   | Адрес | адрес регистрации (в уведомлении обязателен, на сайте не публикуется) |
   | Цели обработки | перенести из раздела 6 политики: запись и исполнение договора об оказании услуг маникюра; связь с клиентом по записи; напоминания о визите; информационные рассылки; публикация фото работ; публикация отзывов клиентов; обеспечение работы и безопасности сайта; исполнение налогового законодательства |
   | Категории персональных данных | ФИО (фамилия и отчество — по желанию), номер телефона, e-mail, день и месяц рождения (год — по желанию), сведения о записях и визитах, комментарий к записи, фото-референс, текст отзыва, заметки о предпочтениях, идентификаторы Яндекс ID и VK ID, Telegram ID, IP-адрес и технические данные. Специальные категории и биометрические — **не обрабатываются** |
   | Категории субъектов | клиенты и зарегистрированные пользователи сайта; посетители сайта; родители и законные представители, записывающие ребёнка |
   | Правовые основания | п. 1, 2 и 5 ч. 1 ст. 6 152-ФЗ; ст. 18 38-ФЗ «О рекламе» (рассылки); гл. 39 ГК РФ (возмездное оказание услуг); 422-ФЗ о НПД (чеки) |
   | Перечень действий и способ обработки | сбор, запись, систематизация, накопление, хранение, уточнение, извлечение, использование, передача (предоставление, доступ), блокирование, удаление, уничтожение; смешанная обработка, с передачей по интернету |
   | Меры защиты (ст. 18.1, 19) | назначен ответственный (сама оператор), опубликована политика, разграничение доступа по ролям, HTTPS, хранение на серверах в РФ, резервное копирование, журналирование доступа, договор поручения с обработчиком (с обязанностью соблюдать конфиденциальность) |
   | Средства криптографической защиты | TLS (HTTPS) при передаче данных |
   | Ответственный за организацию обработки | ФИО оператора, телефон, e-mail |
   | Дата начала обработки | дата открытия регистрации на сайте |
   | Срок или условие прекращения | достижение целей; удаление аккаунта; 3 года после последнего визита; отзыв согласия |
   | Трансграничная передача | **да** — Telegram (страна регистрации оператора сервиса — уточнить по условиям Telegram на дату подачи) |
   | Место нахождения базы данных | Российская Федерация, адрес дата-центра хостинг-провайдера (запросить у хостера) |

3. **Подать уведомление о намерении осуществлять трансграничную передачу** (ч. 3 ст. 12 152-ФЗ) — отдельная форма там же, до начала передачи. Получатель: Telegram (наименование и адрес юрлица взять из условий Telegram / Telegram Gateway); цель: доставка напоминаний о визите и кодов входа; категории данных: имя, номер телефона, Telegram ID, дата и время визита, код подтверждения; категории субъектов: клиенты, давшие согласие на напоминания; правовое основание: согласие. Проверьте, входит ли страна получателя в перечень стран с адекватной защитой (приказ Роскомнадзора от 05.08.2022 № 128): если нет — передачу можно начинать только через 10 рабочих дней после подачи уведомления и при отсутствии запрета Роскомнадзора. Пока уведомление не подано, напоминания в Telegram не включать.

4. **Подписать договор поручения обработки с разработчиком** — шаблон [`poruchenie-obrabotki.md`](poruchenie-obrabotki.md). Без договора разработчик не должен иметь доступа к базе с реальными данными.

5. **Собирать отзывы только через кабинет с галочкой публикации.** Отзыв с именем клиента публикуется на сайте и в канале только при отдельном согласии `reviewPublication` из `consents.ts`. Отзывы из переписки, скриншоты и отзывы без галочки не публиковать; снятый клиентом в кабинете отзыв удалить с сайта и из канала в течение 10 рабочих дней. Примеры в `reviews.ts` (`isExample: true`) заменить только на отзывы, собранные так.

6. **Проверить запись в реестре операторов**: через 30 дней после подачи уведомления найдите себя по ИНН в реестре Роскомнадзора — https://pd.rkn.gov.ru/operators-registry/operators-list/.

7. **При изменении целей, категорий данных, сервисов или хостера** — обновить политику (новая версия и дата в `privacy.ts`) и подать информационное письмо об изменении сведений в реестре не позднее 15-го числа месяца, следующего за месяцем изменения.

8. **Хранить согласия.** Каждое согласие из `consents.ts` — отдельная галочка, по умолчанию не отмеченная; с 1 сентября 2025 года согласие должно оформляться отдельно от других документов. В базе вести журнал: пользователь, вид согласия, версия текста, дата и время, IP-адрес, способ (галочка на сайте), дата отзыва. Журнал хранить столько, сколько хранятся данные, плюс срок исковой давности (3 года).

9. **Подготовиться к инцидентам.** При утечке данных — уведомить Роскомнадзор в течение 24 часов о факте и в течение 72 часов о результатах внутреннего расследования (ст. 21 152-ФЗ). Держите под рукой контакты хостера и разработчика.
